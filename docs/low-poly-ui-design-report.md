# 《无限工时》Low-poly UI 设计方案报告

## 0. 报告性质

- 本报告只做设计，不修改游戏代码、条目、图片、存档或数值。
- 唯一指定的视觉要求是 **low-poly**；其余方向由游戏开发技能路由后决定。
- 路由结果：自定义原生 DOM 引擎，不加载 Phaser、PixiJS、Three.js 或其他引擎技能。
- 使用技能：
  - `game-ui-ux`：HUD、菜单、响应式、屏幕栈、焦点和可访问性。
  - `create-game-assets`：视觉系统、资产家族、统一性与验收门槛。
  - `game-feel`：事件反馈、动效等级、缓动与减少动画。
- 本报告中的图片均为“待制作资产”，当前没有生成或替换任何图片。

## 1. 核心提案：桌面微缩办公室

### 一句话方向

把整个界面设计成一张可以拼装、拆卸和盖章的 **low-poly 微缩办公桌**：工位是模型，设施是零件，升级是工具盒，资源是桌面上的积木账牌，弹窗是夹在桌上的合同板。

### 设计目标

1. **模型感先于面板感**：所有主要组件都有正面、顶面、侧面和接触阴影。
2. **玩法信息先于装饰**：图标、数字和状态在原生尺寸下仍然清晰。
3. **颜色有职责**：芥末黄只表示主动作，珊瑚色只表示提醒，绿色只表示完成。
4. **一个母版扩展全家**：按钮、卡片、资源牌、抽屉和弹窗共享相同的光源、切角和厚度。
5. **轻量 DOM 实现**：不引入 3D 引擎；用 HTML、CSS 和纯矢量 SVG 表现等距模型。

### 不采用

- 全屏霓虹、电竞 HUD、玻璃拟态。
- 纯灰黑后台管理系统。
- 大面积白色网页卡片。
- 每个组件随机切角、随机换色。
- Three.js 场景、照片级材质和实时 3D 光照。
- 把文字烘焙进 SVG 或位图。

## 3. 视觉系统

### 3.1 形状语言

- 基本体块是**矮、厚、宽的六面体**，不是薄网页卡片。
- 普通面板：右上 6px 切角，左下 3px 小折角。
- 主按钮：8px 切角，4px 可见底面。
- 小标签：平行四边形或六边形，禁止胶囊形。
- 奖励：六边形徽章。
- 危险操作：带三角形缺口的块面。
- 禁止同一屏出现多套切角方向。

### 3.2 光源与材质

统一光源位于左上方约 35°：

| 部位 | 表现 |
| --- | --- |
| 顶面 | 主色的明亮面 |
| 正面 | 主色原值 |
| 右侧面 | 主色暗面 |
| 底面 | 最深结构色，2–4px 厚度 |
| 接触阴影 | 右下 2–4px 硬阴影，不使用大面积柔光 |

材质只分四类：

- **墨青塑料**：导航、框架和结构件。
- **奶油纸纤维**：合同、弹窗和说明页，用纯色表现，不加噪点。
- **芥末黄搪瓷**：主操作件。
- **珊瑚色橡胶**：提醒、错误和便签。

### 3.3 视角与细节密度

- UI 组件使用轻微等距投影的二维块面，不做真实透视缩放。
- 工位插画使用三分之四正交视角。
- 64px 图标最多 3 个主要色阶；大型工位最多 5 个。
- 小于 24px 的装饰细节不承载功能。
- 线稿、渐变、滤镜、位图纹理均不进入新 SVG。

### 3.4 灰度与轮廓检查

即使转成灰度，也必须保留：

1. 工位与背景的明度差；
2. 主按钮与次按钮的厚度差；
3. 可购买与不可购买的轮廓/标记差；
4. 当前导航与普通导航的凸起程度差；
5. 已完成与未完成的图标和文字差。

## 5. 布局方案

### 5.1 桌面：办公桌三区域

```text
┌ 公司名称牌 / 职级 / 玩家 ID                 保存 / 成就 / 更多 ┐
├ 工资积木 ┬ 每秒产出积木 ┬ 期权积木 ┬ 影响力积木 ┤
├ 精力条：薄型墨青量尺                                     ┤
│           │                                      │           │
│ 工具抽屉  │        中央微缩工位模型              │ 零件托盘  │
│ 导航      │        退休合同 + 工位 + 技能        │ 设施采购  │
│ 快捷升级  │        实时记录                      │ 单列卡片  │
│           │                                      │           │
└───────────┴──────────────────────────────────────┴───────────┘
```

- ≥1280px：左栏 224px，中央弹性，右栏 340px。
- 901–1279px：左栏 200px，右栏 300px，减少装饰而不减少功能。
- ≥1760px：中央模型最大宽度 760px，额外空间留给桌面，不无限拉伸卡片。
- 右侧设施改为单列横向零件卡，让 low-poly 图标和厚度有足够展示面积。

### 5.2 手机：桌面模型 + 底部零件盒

- 顶部保留名称、保存和更多。
- 资源使用 2×2 积木，不再把四个数字压进一行。
- 工位始终可见，最小场景高度 220px。
- 底部继续使用设施、升级、部门三个入口。
- 抽屉使用底部零件盒，默认占 50dvh；工位和退休入口不被完全遮住。
- 320px 宽度下设施卡使用双列紧凑模式，文字保留名称、价格和数量。
- 使用 `env(safe-area-inset-*)` 保护顶部、底部和手势区域。

### 5.3 缩放策略

- 不对整个 DOM 做固定比例缩放；使用网格、弹性容器和锚定区域。
- 宽屏只扩大桌面留白，不扩大正文行宽。
- 字体提供 100%、125%、150%、200% 选项；200% 时允许卡片变高和列表换行。
- 不通过隐藏关键数字解决小屏溢出。

## 6. 组件规范

### 6.1 公司名称牌

- 墨青厚板，左侧一枚抽象办公桌标志。
- 职级是嵌在板上的芥末黄小标签。
- 保存状态只用文字和小型状态灯，不闪烁。

### 6.2 资源积木

- 四个资源都是相同形状的积木账牌，不做四种颜色。
- 顶面奶油色，正面墨青文字，底面雾青。
- 工资和每秒产出使用大等宽数字。
- 期权用芥末黄六边形图标，不把所有数字都染黄。
- 精力是薄型量尺，以分段块面显示，不用发光渐变。

### 6.3 导航抽屉

- 普通项与左栏处于同一平面。
- 当前项向外凸出 4px，顶面变亮，并带文字标记。
- Hover 只抬起 1px；Focus 使用独立双边框，不与 Hover 混淆。
- 快捷升级是抽屉内的零件格，不额外创建一套视觉语言。

### 6.4 设施零件卡

- 单列横卡：64px 图标、名称、数量、产出、价格、购买增量。
- 可购买：右上出现芥末黄小三角和“可采购”文字。
- 不可购买：卡片不降整体透明度；显示价格缺口或“工资不足”。
- 已购买：显示绿色对勾和数量，不整卡变绿。
- 长按/悬停详情继续使用现有 tooltip，不改为仅 Hover 可发现。

### 6.5 升级与奖杯

- 升级是工具盒中的零件，已购项目嵌入对应槽位。
- 已购合集使用盒盖合拢的形态，不使用额外数字徽章。
- 奖杯使用六边形底座；未解锁时是空槽，不是简单灰色图片。
- 稀有度继续沿用现有 SVG 徽章规则，UI 不发明第二套等级色。

### 6.6 工位模型

工位是唯一的视觉主角：

- 桌面、显示器、键盘、文件夹、台灯、咖啡和绿植组成一个完整微缩模型。
- 显示器内容是低对比抽象图表，真实产值仍由 DOM 文本显示。
- 点击时模型下沉 2px，底面厚度同步减小。
- 工资浮字从显示器上方弹出，粒子使用纸屑多边形，不使用光晕。
- 背景只做三块大色面，避免抢走设施图标的轮廓。

### 6.7 退休合同

- 使用奶油色合同板和芥末黄封条。
- 可退休时封条变为可按压按钮，文案仍明确显示所得期权。
- 不满足条件时保留原因，不用整张灰色卡片掩盖数字。
- 退休确认是新的顶层合同页，焦点落在取消或安全操作上。

### 6.8 弹窗与剧情

- 弹窗是夹在桌面的合同板，纸面为奶油色，正文为墨青色。
- 遮罩使用深墨青 75%，不使用模糊滤镜。
- 主按钮是芥末黄，次按钮是墨青边框。
- 打开时聚焦第一个合理控件；关闭后恢复触发按钮。
- 弹窗内焦点循环，背景控件不可聚焦或点击。

### 6.9 实时记录与 Toast

- 实时记录是桌边的窄打印条，不做聊天消息气泡。
- 普通通知从打印条展开。
- 奖杯通知使用六边形印章和短促纸屑，不进行全屏闪白。

## 8. 动效与反馈分级

### 小反馈：点击、Hover、普通采购

- 2–3 个通道：位移、底面变化、现有音效。
- 90–180ms，ease-out。
- 不震屏、不暂停逻辑、不闪白。

### 中反馈：奖杯、部门加入、技能释放

- 六边形徽章 pop，180–220ms，easeOutBack。
- 4–8 个纸屑多边形，配合现有音效。
- 数字浮字继续使用现有 800ms 左右的上升消退。
- 同一事件只触发一次，结束必须回到静止值。

### 大反馈：退休、投胎

- 合同盖章、封条下落、场景重新拼合，300–350ms。
- 不使用 hit-stop，不打断 Tick，不锁定输入。
- 不做全屏闪烁或相机震动。

### 减少动画

- `prefers-reduced-motion: reduce` 时移除粒子、pop、位移和弹性缓动。
- 保留静态颜色、文字、声音和最终状态。
- 减少闪烁设置用静态着色替代任何闪光。
- 所有动画可取消，取消后直接落到最终语义状态。

## 9. 字体与排版

- 中文正文：`Microsoft YaHei`、`PingFang SC`、系统无衬线。
- 英文标题与数字：`Consolas` 或系统等宽字体，不新增网络字体。
- 页面标题：24px / 700。
- 面板标题：18px / 700。
- 正文：桌面不低于 14px；重要数字 18–24px。
- 辅助文字：不低于 12px；只有非功能装饰编号可使用 10px。
- 数字启用 `font-variant-numeric: tabular-nums`，减少 Tick 更新抖动。
- 间距单位：4、8、12、16、24px；模型厚度只能使用 2、4、8px。

## 10. 输入与可访问性

### 键盘与手柄

- Tab 顺序与视觉顺序一致。
- 每个面板打开都有初始焦点，关闭恢复触发点。
- 弹窗内焦点循环，背景不可交互。
- 手柄方向键/D-pad 移动焦点，A 确认，B 返回，肩键切换同类标签。
- 鼠标移动不能导致当前焦点永久丢失。

### 文字与状态

- 普通文本对比度至少 4.5:1，关键图形和焦点至少 3:1。
- 支持 200% 文本缩放，不裁切关键操作。
- 状态不能只靠颜色，必须有文字、形状或图标。
- 装饰 SVG 使用空 `alt`；独立图标按钮提供可访问名称。
- Tooltip 同时支持悬停、键盘焦点、点击和长按。
- 触控目标不小于 44×44px。

### DOM 与动效实现约束

- 不在带 fixed tooltip 的卡片祖先上直接使用 `clip-path`、`filter` 或 `transform`。
- 多边形卡面由伪元素或内层元素绘制，避免改变 fixed 定位包含块。
- 不为视觉改造重建整个工位 DOM，避免打断焦点和粒子。
- 新反馈只订阅现有事实，不通过 200ms 轮询生成。

- 每个资产记录来源、许可、尺寸、用途、状态和检查结果。

## 12. 推荐实施顺序

### 阶段 1：视觉样板

- 工位模型、一个资源积木、一张设施卡、一个主按钮。
- 在桌面与手机原生尺寸下审查轮廓、明度、厚度和数字可读性。
- 样板未通过前不扩展全部 UI。

### 阶段 2：核心组件

- 建立语义色板、厚度、间距和状态变量。
- 推广到导航、采购数量、升级格、退休合同。
- 保持现有 DOM ID、`data-action` 和命令分发不变。

### 阶段 3：面板与响应式

- 统一辅助抽屉、剧情弹窗、Royal Market、Toast。
- 完成 2×2 手机资源布局、底部零件盒和安全区。

### 阶段 4：反馈与验收

- 接入现有 Domain Facts 的动效等级。
- 完成减少动画、200% 文本、键盘/手柄和性能检查。

## 13. 验收清单

### 视觉

- [ ] 工位、资源积木、设施卡在同一光源和厚度体系下。
- [ ] 原生尺寸与灰度下都能识别主操作和状态。
- [ ] 没有随机切角、色彩漂移或多套图标风格。
- [ ] 亮色面积受控，现有 SVG 轮廓不被背景吞没。

### 功能与布局

- [ ] 320、390、768、1024、1440、2560×1080 下无横向溢出。
- [ ] 现有采购、升级、退休、剧情、存档和提示流程不变。
- [ ] 手机抽屉不遮挡全部工位，焦点不被固定栏覆盖。
- [ ] 200% 文本缩放后关键内容仍可见。
- [ ] `npm test` 通过；浏览器验收必须另行获得用户同意。

### 动效与性能

- [ ] 连续触发时动画不会叠加失控，结束回到静止值。
- [ ] 无全屏闪烁、无常规震屏、无 hit-stop。
- [ ] 减少动画模式下没有非必要位移和粒子。
- [ ] 新反馈不增加逐帧状态扫描，不改变 Tick 或数值逻辑。

## 14. 当前结论

“桌面微缩办公室”可以把 low-poly 从单纯切角提升为完整的产品视觉系统：有明确的模型、材质、光源、颜色和反馈规则，同时能直接用现有 DOM 与 SVG 管线实现，不需要引入 3D 引擎。

下一步只需要制作并审查一个视觉样板：**微缩工位 + 资源积木 + 设施零件卡 + 主按钮**。样板通过后，再推广到整个界面。
